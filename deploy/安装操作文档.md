# LibreDesk 服务器安装操作文档

本部署包来自当前项目源码提交 `41bcf70f`，使用单台 Linux 服务器运行 LibreDesk、PostgreSQL 和 Redis，通过服务器 IP 直接访问。LibreDesk 程序内已包含管理后台、网站聊天组件、语言包和数据库初始化文件。安装过程需要访问容器镜像仓库及 Alpine 软件包仓库。

**此方案使用 HTTP，账号密码和客服数据在网络传输时不加密，建议仅用于可信内网或临时测试。** 示例配置为支持 HTTP 登录而关闭了 Secure Cookie。HTTPS 网站通常无法嵌入 HTTP 聊天组件；公网正式使用应另行配置可信 HTTPS 入口，并恢复 Secure Cookie。

## 一、安装前准备

1. 一台 Linux 服务器，安装 Docker Engine、Docker Compose 插件和 OpenSSL，确认 `docker compose version` 可以运行。以下命令在 Linux shell 中执行，假定当前用户可以运行 Docker；否则按服务器配置使用 `sudo`。
2. 服务器上 TCP 9000 端口空闲，且防火墙和云安全组允许需要访问的客户端连接。建议仅允许内网或指定来源访问。
3. 用 `uname -m` 查看架构：`x86_64` 选 `linux-amd64` 包；`aarch64` 或 `arm64` 选 `linux-arm64` 包。不要混用。
4. 需要持久保存 Docker 的数据卷。建议为应用、数据库和上传文件预留足够空间，并定期做异地备份。

以下以 `linux-amd64` 压缩包为例，ARM64 请替换为对应文件名。

## 二、上传和配置

将压缩包上传到服务器，例如 `/opt`，然后解压：

```sh
cd /opt
mkdir -p libredesk
tar -xzf libredesk-linux-amd64.tar.gz -C libredesk
cd libredesk
ls -la
```

目录应包含 `libredesk`、`compose.yaml`、`Dockerfile`、`config.sample.toml`、`INSTALL.md` 和 `.env.example`。

创建配置并生成独立随机密钥：

```sh
cp .env.example .env
chmod 600 .env
sed -i "s/^ENCRYPTION_KEY=.*/ENCRYPTION_KEY=$(openssl rand -hex 16)/" .env
sed -i "s/^POSTGRES_PASSWORD=.*/POSTGRES_PASSWORD=$(openssl rand -hex 24)/" .env
```

默认对外端口为 `9000`；若已被占用，可编辑 `.env` 修改 `APP_PORT`，并相应调整防火墙与访问地址。例如：

```sh
nano .env
```

加密密钥用于保护系统中保存的敏感配置。**部署后请安全备份 `.env`，不要随意更换加密密钥或数据库密码。** 数据库卷初始化后，单独修改 `.env` 中的数据库密码不会自动修改已有数据库账号密码。

## 三、启动与设置管理员密码

```sh
docker compose config --quiet
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 app
```

首次启动会创建独立数据库并执行安装和升级。首次安装可能需要等待镜像下载与数据库启动。检查应用日志确认数据库安装和服务启动成功后，设置系统管理员密码：

```sh
docker compose exec app ./libredesk --set-system-user-password --config /libredesk/config.toml
```

按提示输入强密码，然后访问 `http://服务器IP:9000`，用户名填写 `System`。如果修改了 `APP_PORT`，访问时使用对应端口。登录后在管理后台通用设置中将公开访问地址设置为实际访问地址，并按需要选择简体中文。部分中文翻译尚不完整。

检查健康状态：

```sh
curl -fsS http://服务器IP:9000/health
```

该健康接口主要检查数据库连接；返回成功并不等于邮件、WhatsApp 或 AI 等外部服务都正常。请在后台配置相关服务后分别测试。

> 本方案仅适用于新的独立数据库。应用启动时使用幂等安装和升级；普通 `--install` 可能清空数据库，请勿对已有业务数据库执行普通安装。

## 四、网站接入聊天

在后台创建启用的 Live Chat 收件箱，设置外观、语言和可信域名，复制后台生成的安装代码。示例：

```html
<script>
  window.LibredeskSettings = {
    baseURL: 'http://服务器IP:9000',
    inboxID: '替换为后台生成的收件箱 UUID'
  };
</script>
<script async src="http://服务器IP:9000/widget.js"></script>
```

将代码加入网站全局模板。收件箱语言可直接设置为简体中文；若选择自动语言，可增加 `language: 'zh-CN'`。该 HTTP 示例适用于 HTTP 网站或内网测试；HTTPS 网站不能依赖 HTTP 组件正常加载。若网站使用 CSP，请放行 LibreDesk 地址用于脚本和 iframe；可信域名应包含实际嵌入网站的来源。

如需绑定网站登录用户，应由网站**后端**使用收件箱 Secret Key 签发 JWT，并通过 `userJWT` 传给组件；不要把 Secret Key 放到前端。完成配置后，请用访客和客服两个浏览器实际测试消息收发。

## 五、常用运维

```sh
docker compose ps
docker compose logs -f app
docker compose restart app
docker compose stop
docker compose up -d
```

本部署将应用的 9000 端口映射到服务器的 `APP_PORT`；PostgreSQL 和 Redis 不发布到宿主机端口。应用是单实例部署。

## 六、备份与升级

至少备份数据库、上传文件和 `.env`，并定期在独立测试环境验证恢复。以下命令在部署目录执行，备份文件包含客户数据，应妥善保管：

```sh
mkdir -p backup
docker compose exec -T db pg_dump -U libredesk -d libredesk -Fc > backup/libredesk.dump
docker compose run --rm --no-deps --entrypoint tar app -czf - -C /libredesk/uploads . > backup/uploads.tar.gz
cp .env backup/env.backup
chmod 600 backup/libredesk.dump backup/uploads.tar.gz backup/env.backup
```

如需严格一致的备份，先安排停机并停止应用写入，再执行备份；Redis 持久卷包含会话与部分队列数据，应结合业务恢复目标另行备份。

升级前先备份。将新版本对应架构的 `libredesk` 文件替换部署目录中的旧文件，保留 `.env` 和 Docker 数据卷，然后运行：

```sh
docker compose up -d --build app
docker compose logs --tail=100 app
```

启动流程会执行数据库升级。请先在测试环境验证升级；数据库迁移后，不能假定直接换回旧二进制就能回滚，应准备经过验证的数据库和文件备份。

不要对生产环境运行 `docker compose down -v`，该命令会删除本方案的数据卷。

## 七、排查

- 无法打开网站：检查服务器 IP、9000 端口（或设置的 `APP_PORT`）、防火墙、安全组和应用日志。
- 应用启动失败：检查 `docker compose ps`、应用日志、`.env` 中 32 字符加密密钥及数据库密码。
- 聊天组件不显示：检查浏览器控制台、组件收件箱是否启用、安装代码中的域名和 UUID、可信域名与网站 CSP。
- 实时消息不更新：检查浏览器能否建立 WebSocket 连接；如果另加代理，确认它支持 WebSocket。
- 健康检查成功但通知或渠道异常：分别检查邮件、Meta、AI 等对应外部服务的配置与日志。
